# 08 · 工作流与提示词模板

## 1. 总流程

```
选任务 → 读文档 → 翻译 → 自检 → 验证 → 汇报 → 更新 PROGRESS → （独立会话）审查
```

- **自底向上：** 先做无依赖的叶子模块，每层验证通过再进入下一层（见 `00` 里程碑）。
- **小粒度：** 每次一个文件，或一个大文件中的一组函数。
- **审查用独立会话：** 翻译者和审查者不是同一个会话，避免自我确认。

## 2. 任务模板

### 2.1 翻译一个文件

```
请先阅读 CLAUDE.md 与 docs/00、03、06，并查看 docs/04 确认该文件未被翻译。

任务：翻译 <C++ 路径> 到 <Rust 路径>。
相关依赖（已翻译，可直接引用）：<列出 Rust 文件>
参考的 C++ 头文件：<列出>

要求：
- 逐函数对应，保持顺序，不得省略；每个函数写 `// Ported from:` 标注。
- 不确定处写 TODO(translate)，并登记 docs/04，不要猜。
- 不修改其他文件。
- 完成后运行 cargo fmt / clippy / test，并按 docs/08 的汇报模板回复。
```

### 2.2 审查（独立会话）

```
你是审查者，不要修改代码。请对照 <C++ 文件> 与 <Rust 文件>：
1. 列出 C++ 中存在、Rust 中缺失的函数/分支/常量。
2. 逐函数检查语义差异：数值类型、运算顺序、边界条件、RNG 调用顺序、循环遍历顺序、switch fallthrough。
3. 检查是否出现了 03 中的禁止项。
4. 输出差异清单，每条包含：位置（两边行号）、问题、严重程度（会影响回放 / 仅风格）、建议。
没有发现问题的函数也要列出"已核对"。
```

### 2.3 修复与 C++ 不一致

```
症状：<例如：第 N 帧起状态哈希与 C++ 不一致>
已知：<首次不一致的帧号、字段>
任务：定位原因。先只输出分析（涉及的 C++ 与 Rust 函数、可疑点、验证方法），经确认后再修改。
修复后必须补一个能复现该问题的测试。
```

### 2.4 恢复上下文（新会话）

```
请阅读 CLAUDE.md 与 docs/04_PROGRESS.md，总结：当前阶段、最近完成项、未解决 TODO、需要返工项。
然后等待我指派任务，不要主动开始翻译。
```

## 3. 汇报模板（AI 完成任务后必须使用）

```
## 完成情况
- 翻译文件：<C++> → <Rust>
- 函数对应：C++ N 个 / Rust M 个（逐个列出缺失项及原因）

## 自检结果
- cargo fmt：通过/未通过
- cargo clippy -D warnings：通过/未通过（如有 allow，列出原因）
- cargo test：通过/未通过（贴摘要）

## 不确定与 TODO
- <位置>：<问题>（已登记 04）

## 与 C++ 的已知差异 / UB 处理
- <无 / 列出>

## 触及的决策
- 遵循了 ADR-xxx；遇到未覆盖问题：<无 / 列出，等待决定>

## 已更新的文档
- docs/04_PROGRESS.md：<说明>
```

**汇报中不允许出现的话：**"应该没问题""理论上等价"而没有证据。必须附实际命令输出或具体对照依据。

## 4. 机器可检查的约束（建议在 `tools/` 实现）

| 脚本 | 作用 |
|---|---|
| `tools/check_parity.py` | 解析 `cpp/src` 与 `src` 的函数名，按 `// C++: 文件:行号` 对照；缺失或体量悬殊即报告（可复用 ANALYSIS_REPORT §11 的复现方法） |
| `tools/check_headers.py` | 检查翻译函数是否有 `// C++:` 标注、每条 `TRANSLATION_NOTE` 是否已登记到 `04` |
| `tools/check_forbidden.sh` | 对比 git diff：**新增行**中出现 `static mut`、`f64`、`Box::from_raw`（需审查）、`unwrap()`、无 `SAFETY` 注释的 `unsafe` 即报警（存量不报） |
| `tools/replay_diff.py` | 对 C++ / Rust 回放输出的状态摘要逐帧比对，输出第一个不一致的帧 |
| CI | `fmt` + `clippy -D warnings` + `test` + 上述脚本 |

> 文档是"软约束"，脚本与回放测试才是"硬约束"。

## 5. 维护本套文档

- 发现 AI 犯了新类型的错误 → 补到 `06` 第 10 节。
- 规则变更 → 在 `04` 的"需要返工"中列出受影响文件。
- 文档保持简短、具体、用"必须/禁止"；示例比描述更有效。
