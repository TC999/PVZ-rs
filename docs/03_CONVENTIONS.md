# 03 · 代码规范与禁令

## 1. 来源标注（强制）

沿用仓库现有格式（已有约 730 处）：

```rust
// C++: Challenge.cpp:2540-2741
pub fn init_zombie_waves(&mut self) { … }
```

要求：
- 行号必须能在 `cpp/src/` 中核对；找不到对应物时写 `// RUST-ONLY: 原因`。
- 与 C++ 有意不同的地方，用 `// [TRANSLATION_NOTE]: <差异与原因>`（已有约 560 处）。**每条 TRANSLATION_NOTE 必须同时登记到 `04_PROGRESS.md` 的"已知差异"表**，否则等于没写。
- 文件头：`//! C++: <相对 cpp/src 的路径>`。

## 2. 逐函数对应

- 每个 C++ 函数对应一个 Rust 函数，**顺序尽量保持一致**，便于对照。
- 函数内部的语句顺序、分支结构、计算顺序保持一致。
- 允许的改写：语法层面的等价转换（如 `for(;;)` → `loop`、`switch` → `match`）。`switch` 的 fallthrough 必须显式展开，并用注释标明。
- 不允许：提取"公共逻辑"为新函数、合并相似分支、提前返回重构、把循环改为迭代器链（除非完全等价且已确认顺序/副作用无影响）。

## 3. unsafe、裸指针与释放（本仓库特有）

现状：约 2700 处 `unsafe`、1265 处裸指针、217 处 `static mut`。**不要求现在消灭，但要求不再恶化。**

| 规则 | 说明 |
|---|---|
| 新增 `static mut` | **禁止** |
| 新增 `unsafe` | 允许，但必须最小范围，并写 `// SAFETY: <指针来源与存活保证>` |
| 重构既有 unsafe | 不在翻译任务内；需单独立项 |
| **延迟释放（重点）** | 不得在一个对象的方法执行期间释放该对象自身（或其所有者）。C++ 的 `SafeDeleteWidget` 是把 Widget 放进 safe-delete 列表，在主循环安全点统一释放；Rust 必须等价，**不得 `Box::from_raw` 立即释放** |
| 裸指针存活 | 释放对象前，必须从所有持有它的容器/父级中移除；释放后不得再访问 |

示例（当前代码的风险点，见 `07` §4）：`LawnApp::loading_completed()` 在 `TitleScreen` 自己的 `update` / `button_depress` 中被调用，并立即 `Box::from_raw` 释放 TitleScreen —— 调用栈上的 `self` 随即悬空。

## 3.1 其他禁止事项

| 禁止 | 说明 |
|---|---|
| `f64` 替代 `f32` | 数值漂移（仓库中现有 `f64` 约 357 处，逐步核对是否对应 C++ `double`） |
| `usize` 替代 `i32/u32` | 影响回绕与比较 |
| 随意 `as` 转换 | 每处与 C++ 转换语义一致 |
| 不稳定排序 `.sort()` | 对照 C++ 是 `std::sort` 还是 `stable_sort` |
| `HashMap`/`HashSet` 的遍历顺序影响游戏逻辑 | 改用有序结构并登记 |
| 新增依赖 | 先问 |
| 修改无关文件、混入重构/格式化 | 单独提交 |
| 固定常量替代随机/计算（如"恒取首项"） | 视为假完成，见 CLAUDE.md |

## 4. 错误处理策略

| 场景 | 做法 |
|---|---|
| 启动期：文件缺失、解析失败、资源不存在 | 返回 `Result`，向上传递，最终给出明确错误信息并退出 |
| 游戏逻辑中 C++ 原本有 `assert` / 检查 | `debug_assert!` 或保持相同的显式分支 |
| 游戏逻辑中 C++ 原本会 UB（越界、空指针） | **不要静默吞掉。** 登记到 `06_BEHAVIOR_SPEC.md` 的"UB 清单"，在代码处写 `// UB-IN-ORIGINAL: 说明`，行为取值见该清单 |
| `unwrap()` | 现有约 109 处；新增仅允许在测试代码，或有注释证明永不失败的位置 |
| 任何线程中的 `panic` | 必须让整个进程以可见方式退出（见 `07`），不允许吞掉 |

## 5. 工具与质量门槛

当前基线：`cargo check` → 0 error / ~750 warnings。

**每次提交必须：**

```
cargo fmt --check
cargo check          # warning 数不得高于基线；新增代码不得引入新的 never-used 告警
cargo test --workspace
```

- never used / never constructed 告警是"**没有接线**"的机器证据：新增函数必须被调用，否则登记为未接线。
- `cargo clippy -- -D warnings` 作为**目标**：先对新文件启用，存量逐步清理。若 clippy 建议会改变行为，用 `#[allow(...)]` 并说明原因。
- 本地调试加速：见 `07` §3，`dev` 配置的 `opt-level` 建议调高，否则图片解码在 debug 下极慢。

## 6. 测试要求

| 模块类型 | 测试 |
|---|---|
| 纯函数（数学、字符串、解析） | 单元测试 + **golden 文件**（由 C++ 版生成） |
| 存档 | 与 `scripts/pvzp-v4-converter.py` 导出的 YAML 对照 |
| 游戏逻辑 | `.dmo` 回放哈希对照（见 `06`） |
| 回归 | 每次修复翻译错误，补一个能复现该错误的测试 |

## 7. 提交规范

- 一个提交只做一件事：一个文件或一组紧密相关的函数。
- 提交信息格式：`port(<module>): <C++文件> → <Rust文件>（M? 阶段）`
- 返工：`fix(port): <文件/函数> 与 C++ 行为不一致：<现象>`
- 修改 ADR：`adr: <编号> <标题>`

## 8. 对 AI 的输出要求

- 先说明将修改哪些文件，再改。
- 给出代码时给出完整函数，不要使用 `// ... 其余不变`、`// 省略` 这类占位。
- 汇报使用 `08_WORKFLOW.md` 中的模板。
